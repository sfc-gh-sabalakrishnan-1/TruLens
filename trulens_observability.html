Snowflake AI Observability

One place to watch
every AI agent you run.

TruLens is the open-source observability SDK that Snowflake wires into AI Observability. It captures the full execution tree of an AI app — planning, tool calls, retrieval, generation — and lands it as governed data inside your Snowflake account. Whether the agent is a native Cortex Agent or your own custom app running anywhere, the traces end up in the same table and the same Snowsight experience.

Cortex Agents — native Custom apps — External Agent Traces + evaluations Governed in Snowflake
What it exposes

Not just a score at the end — every step in between.

TruLens instruments your application so each function emits a span. You get visibility into what was retrieved, what the model produced, how long each step took, what it cost, and — on demand — an LLM-judge score with an explanation.

01

Execution traces

Inputs and outputs per span, latency, intermediate steps, tool calls, and retrieved context — the full path from question to answer.

02

Evaluations

Batch runs over a dataset with LLM-as-a-judge metrics, plus per-record and aggregate scores you can compare across app versions.

03

Cost & latency

Token usage and cost per LLM call (from AI_COMPLETE) and per-function latency, rolled up to an average across every input.

04

Version comparison

Run the same dataset against different prompts, models, or retrievers and diff the results to pick the best version to ship.

05

Judge explanations

Every score comes with a reason from the LLM judge, so a low groundedness or relevance score points you to the record that caused it.

06

SQL access

Everything is queryable. Traces and scores live in a Snowflake table you can join, filter, and build dashboards on.

context_relevance — Does the retrieved context match the user query? (RETRIEVAL.QUERY_TEXT + RETRIEVED_CONTEXTS)

groundedness — Is the answer supported by the retrieved context? (RETRIEVED_CONTEXTS + RECORD_ROOT.OUTPUT)

answer_relevance — Is the response relevant to the question? No ground truth needed. (INPUT + OUTPUT)

correctness — How closely does the answer match the expected answer? (INPUT + GROUND_TRUTH_OUTPUT + OUTPUT)

coherence — Is the response logically consistent? (RECORD_ROOT.OUTPUT)

cost & latency — Token cost and per-step latency, captured automatically from the spans.

What it captures

Not just RAG. Any Python AI app — any model, any step.

RAG is only the most common example. TruLens instruments any Python function, so it traces agents, tool calls, MCP calls, multi-agent graphs, and workflows. It also captures LLM calls whether the model runs inside Snowflake Cortex or with an external provider. Each step becomes a typed span, and you can score any span — or the whole trace — with the metric family that fits.

Every family of metrics

Filter by where the metric runs. Server-side metrics are built into Snowflake: you request them by name and a Cortex model acts as the judge. Both kinds are attached to the same run and appear in Snowsight.

Set expectations clearly

  • Python applications. Snowflake AI Observability with TruLens supports applications written in Python.
  • Only what's instrumented is captured. A step appears in the trace only if it is instrumented or emitted inside a TruLens recording. Spans started outside a recording are dropped.
  • Five metrics are available by name on the server. Agent GPA, safety, extended quality, and custom metrics are added as client-side metrics through the Metric API.
  • Cost for external LLMs. Snowflake documents automatic cost calculation for Cortex LLM calls. Cost for external models depends on TruLens provider cost tracking, so validate it in your account before relying on it.
  • Guardrails are separate. Cortex AI Guardrails apply to CoCo, CoWork, and Cortex Agents, not to TruLens External Agents.
The telemetry tree

A request becomes a tree of spans.

Both native agents and TruLens-instrumented apps emit OpenTelemetry-style spans. Snowflake organizes them as a hierarchy: a thread holds turns, each turn is one trace, and a trace is made of spans for each meaningful step.

# One conversation, decomposed

Thread                          ← the whole conversation
 └─ Turn  (one user request)     ← one question / prompt
     └─ Trace  (trace_id)         ← one end-to-end execution
         ├─ span : Planning
         ├─ span : Tool call  → Cortex Search   (retrieval)
         ├─ span : Tool call  → Cortex Analyst  (text-to-SQL)
         ├─ span : Chart generation
         └─ span : Response generation      (the answer)

# Each span stores: inputs, outputs, latency, tokens, cost,
# tool name, errors -- and, after an eval run, judge scores.
Two ways in, one destination

However the agent is built, the telemetry lands in the same place.

Pick the path that matches how the agent was built. A native Cortex Agent logs itself automatically. A custom app — your own RAG pipeline, a LangGraph agent, anything running on Snowpark Container Services or off-platform — is instrumented with the TruLens SDK and registered as an External Agent.

The key idea: the External Agent object stores only metadata (application name, version, run name). It does not store your application code, prompts, traces, or scores — those all live in AI_OBSERVABILITY_EVENTS.

Where it lands

One event table holds all of it.

Traces and evaluation results — from Cortex Agents, CoWork, CoCo, Cortex Search, and TruLens External Agents — are stored together in a single Snowflake-managed table. Rows are immutable once ingested.

THE TABLE

SNOWFLAKE.LOCAL.AI_OBSERVABILITY_EVENTS

Holds threads → turns → traces → spans, the inputs/outputs per span (subject to redaction), user feedback on responses, and evaluation runs for both Cortex Agents and External Agents. Rows can't be modified after ingestion.

ACCESS

Roles & redaction

SNOWFLAKE.AI_OBSERVABILITY_READER grants read access; SNOWFLAKE.AI_OBSERVABILITY_ADMIN can delete rows. The account privilege READ UNREDACTED AI OBSERVABILITY EVENTS TABLE controls whether roles see full tool inputs, outputs, and conversation text — without it, metadata like tool names, latency, and token counts is still visible.

Traces are separate from billing. Credits, tokens, and request metadata for most AI features are recorded in Account Usage views (for example CORTEX_AGENT_USAGE_HISTORY). The telemetry tree lives in AI_OBSERVABILITY_EVENTS — think "what happened" vs. "what it cost."

Native vs TruLens — crisp

Same table. Same Snowsight. Different entry point.

This is the question most customers ask: if Cortex Agents already have observability, what does TruLens add? The honest answer — they are two doors into the same room, chosen by who built the agent.

Built in Snowflake

Cortex Agent observability

For agents you create as native Cortex Agents (incl. Snowflake CoWork / Snowflake Intelligence).

  • You writeNothing — logging is automatic once the agent runs.
  • WhereAI & ML ▸ Agents ▸ Observability + Evaluations tabs.
  • Live viewReal production threads and traces as they happen.
  • MetricsGoal-Plan-Action: tool selection, tool execution, answer correctness, logical consistency.
  • Best forAgents composed of Cortex tools, deployed through the Agent API or CoWork.
Built by you

TruLens External Agent

For custom apps that are not a single native Cortex feature — your own RAG, LangGraph/LlamaIndex agents, multi-step workflows.

  • You writeInstrument functions with @instrument() and register with TruApp.
  • WhereAI & ML ▸ Evaluations (as an External Agent).
  • Live viewOptional live tracing; primarily batch runs over a dataset.
  • MetricsContext relevance, groundedness, answer relevance, correctness, coherence + custom metrics.
  • Best forApps hosted anywhere — Snowpark Container Services, another cloud, or on-prem — that you own end to end.

What TruLens brings you beyond Cortex Agent observability: it extends the exact same tracing, scoring, and Snowsight experience to code Snowflake didn't build and doesn't host. If your agent is a native Cortex Agent, you already have observability — use it, no SDK required. The moment you have custom retrieval logic, a non-Cortex orchestration framework, or an app running off-platform, TruLens is how that telemetry still lands in your governed Snowflake account and shows up next to everything else.

USE ROLE ACCOUNTADMIN;

GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER   TO ROLE AI_OBSERVABILITY_APP_ROLE;
GRANT USAGE ON SCHEMA EVAL_DB.EVAL_SCHEMA  TO ROLE AI_OBSERVABILITY_APP_ROLE;

-- register apps, run evaluations, and let the LLM judge run
GRANT CREATE EXTERNAL AGENT ON SCHEMA EVAL_DB.EVAL_SCHEMA TO ROLE AI_OBSERVABILITY_APP_ROLE;
GRANT CREATE TASK          ON SCHEMA EVAL_DB.EVAL_SCHEMA TO ROLE AI_OBSERVABILITY_APP_ROLE;
GRANT EXECUTE TASK        ON ACCOUNT                    TO ROLE AI_OBSERVABILITY_APP_ROLE;
GRANT USE AI FUNCTIONS    ON ACCOUNT                    TO ROLE AI_OBSERVABILITY_APP_ROLE;

from trulens.core.otel.instrument import instrument
from trulens.otel.semconv.trace import SpanAttributes

class SupportRAG:
    @instrument(
        span_type=SpanAttributes.SpanType.RETRIEVAL,
        attributes={
            SpanAttributes.RETRIEVAL.QUERY_TEXT: "query",
            SpanAttributes.RETRIEVAL.RETRIEVED_CONTEXTS: "return",
        },
    )
    def retrieve_context(self, query: str) -> list:
        return self.retriever.retrieve(query)   # Cortex Search / vector DB

    @instrument(span_type=SpanAttributes.SpanType.GENERATION)
    def generate(self, query, contexts) -> str:
        return complete_with_cortex(query, contexts)

    @instrument(span_type=SpanAttributes.SpanType.RECORD_ROOT)
    def answer_query(self, query: str) -> str:
        return self.generate(query, self.retrieve_context(query))
from trulens.apps.app import TruApp
from trulens.connectors.snowflake import SnowflakeConnector

# Pass an existing Snowpark session -- no password needed
connector = SnowflakeConnector(snowpark_session=session)

app = SupportRAG()

# TruApp registers the app and auto-creates the EXTERNAL AGENT object.
# You do NOT need to run CREATE EXTERNAL AGENT by hand.
tru_app = TruApp(
    app,
    app_name="SUPPORT_RAG",
    app_version="v1",
    connector=connector,
    main_method=app.answer_query,
)
import time, pandas as pd
from trulens.core.run import RunConfig

df = pd.DataFrame([
    {"question": "How do I reset my password?",
     "ground_truth": "Verify identity, then reset in Account Settings."},
])

run = tru_app.add_run(run_config=RunConfig(
    run_name="support_rag_eval_v1",
    source_type="DATAFRAME",
    dataset_name="support_eval",
    dataset_spec={
        "RECORD_ROOT.INPUT": "question",
        "RETRIEVAL.QUERY_TEXT": "question",
        "RECORD_ROOT.GROUND_TRUTH_OUTPUT": "ground_truth",
    },
    llm_judge_name="llama3.1-70b",   # default judge
))

run.start(input_df=df)                     # invokes app, writes traces
while run.get_status() != "INVOCATION_COMPLETED":
    time.sleep(3)                          # wait for ingestion

run.compute_metrics(metrics=[
    "context_relevance", "groundedness",
    "answer_relevance", "correctness", "coherence",
])

# An agent that calls an EXTERNAL LLM (OpenAI here) and a tool,
# evaluated with server-side metrics + client-side Agent GPA metrics.
from openai import OpenAI as OpenAIClient
from trulens.core import Metric, Selector
from trulens.providers.cortex import Cortex

client = OpenAIClient()

class SupportAgent:
    @instrument(span_type=SpanAttributes.SpanType.TOOL)
    def lookup_account(self, account_id: str) -> dict:
        return crm.get(account_id)                # your tool / MCP call

    @instrument(span_type=SpanAttributes.SpanType.GENERATION)
    def call_external_llm(self, prompt: str) -> str:
        r = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
        )
        return r.choices[0].message.content

    @instrument(
        span_type=SpanAttributes.SpanType.RECORD_ROOT,
        attributes={SpanAttributes.RECORD_ROOT.INPUT: "question",
                    SpanAttributes.RECORD_ROOT.OUTPUT: "return"},
    )
    def ask(self, question: str) -> str:
        facts = self.lookup_account("ACME-001")
        return self.call_external_llm(f"{facts}\n\n{question}")

# Judge for client-side metrics: a Cortex model (or OpenAI, Bedrock, LiteLLM ...)
judge = Cortex(snowpark_session=session, model_engine="claude-sonnet-4-5")
whole_trace = {"trace": Selector(trace_level=True)}

agent_metrics = [
    Metric(implementation=judge.tool_selection_with_cot_reasons,      name="Tool Selection",       selectors=whole_trace),
    Metric(implementation=judge.tool_calling_with_cot_reasons,        name="Tool Calling",         selectors=whole_trace),
    Metric(implementation=judge.execution_efficiency_with_cot_reasons, name="Execution Efficiency", selectors=whole_trace),
    Metric(implementation=judge.logical_consistency_with_cot_reasons,  name="Logical Consistency",  selectors=whole_trace),
]

# ... register with TruApp, add_run, run.start(input_df=df) as in step 4 ...

run.compute_metrics(metrics=[
    "answer_relevance", "coherence",   # server-side, by name
    *agent_metrics,                        # client-side Agent GPA
])
